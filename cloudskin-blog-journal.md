## Engine (js/blog.js)
- `window.CLOUDSKIN_WP.url` = WP REST base (site URL + `/wp-json/wp/v2`). EMPTY = 4 bundled bilingual SAMPLE posts (real CloudSkin editorial, native EL+EN, no lorem, no em-dashes, no invented facts), clearly flagged in the UI via the `#jNote` preview banner. ## GOTCHA (new, durable) — nested clean-URL route breaks root-less relative paths
`/blog/<slug>` lives one path segment deep, so a page's own `js/…`,`css/…`,`img/…` refs AND the shared header/footer/menu's relative links (`collection.html`, `about.html`) resolve under `/blog/` and break. serve.mjs's `/blog/*` catch-all MASKS it locally (returns 200 but serves blog-post.html as the "asset"); on Vercel the `/blog/:slug` rewrite is single-segment so `/blog/js/x.js` HARD-404s. Fix applied: (1) all blog-page asset paths made ROOT-relative (`/js/…`), (2) sample covers root-relative (`/img/…`), (3) a document-wide chrome-link normalizer `fixChromeLinks()` in blog.js runs after the shell renders and rewrites root-less relative `<a href>`s to root-relative — deliberately NOT `<base href="/">`, which would have broken the skip-link, footer `#top` and JS-handled `#` links. Verified: post page renders full SEO + body + covers + continue-reading, chrome links resolve to `/collection.html`, 0 console errors, 0 overflow at 320/360/390.

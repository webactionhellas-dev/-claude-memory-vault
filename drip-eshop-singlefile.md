`C:\Users\nospa\Downloads\drip-store-eshop.html` is a standalone single-file e-commerce site for "DRIP" (luxury sneakers/streetwear, Athens). ~18MB because product photos (and originally Inter/Archivo) are inlined as base64. Architecture: one giant `<script>` holds `const DATA` (311 products, base64 JPEG/PNG images), `const META`, `const LOGO`; a second `<script>` is the `DRIP` module + hash router (home / shop / product / wishlist).

**Brand/theme (as of 2026-06-20):** shares the DRIP Barbershop identity (`C:\Users\nospa\Downloads\dripbarbershop (1) (1) (1).html`, same business) — Tiffany teal accent `#15DED5` (lt `#5FF2EC`, deep `#0BA39B`, ink-on-teal `#04201f`), near-black bg `#030405`/`#0B0C0D`/`#121315`, fonts **Oswald** (display) + **PT Sans** (body) via Google Fonts `<link>`. Signature touches: eyebrows are teal with a 24×2px bar (`::before` currentColor), marquee bullets are teardrop drips (`border-radius:50% 50% 50% 0;rotate(45deg)`), teal glow on fill buttons. The embedded Inter/Archivo @font-face still sit in the head (harmless, unused). When re-theming, the accent lives in `--accent` + hardcoded `rgba(21,222,213,…)` glows.

**Why:** This is a DIFFERENT project from [[drip-store-site]] (the cinematic Next.js 15 + R3F build in claude projects/drip-store). Don't confuse them. The barbershop is the sibling site that defines the shared brand look.

**How to apply:** The base64 `DATA`/`META`/`LOGO` line is too large to read into context — never rewrite it. To edit, splice: keep the head/fonts + data block byte-exact (sed extract), replace only the CSS `<style>` and app `<script>` blocks, then `cat` back together. **2026-06-21 — optimization pass on the `(1)` variant:** The user's working file is `C:\Users\nospa\Downloads\drip-store-eshop (1).html`, which had grown to **47.4MB** after they inlined all product photos (982 base64 images, 977 unique, 34.7MB of image data; title "DRIP — Luxury Sneakers & Streetwear in Athens", Inter/Archivo fonts, near-black `#050505` theme — note this differs from the teal/Oswald description above, may be a separate export). Two real issues found & fixed: (1) **41 single-photo products displayed their photo as a 72px speck** — `.gallery{grid-template-columns:72px 1fr}` reserved a thumb column even when `.thumbs` wasn't rendered; fixed with `.main-img:only-child{grid-column:1/-1}`. NOT a missing-data problem — all 311 products had 1–4 valid photos; none broken; no external photo source exists to add more angles. (2) **Downsized via `sharp`**: re-encoded every image to WebP q72, resized long-edge to 660px (display slots max ~654px so visually lossless), keeping all photos → **16.6MB** output at `drip-store-eshop-optimized.html`. Pipeline lives in `C:\Users\nospa\Downloads\_drip_work\build.js` (+ sharp in node_modules); a higher-quality 20.9MB q76/720px variant is also achievable. Per-image stats / DATA parsing: extract `const DATA = ` line (base64 has internal `;` so split on `\nconst META`), JSON.parse.

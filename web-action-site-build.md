`C:\Users\mikef\web-action-site` is the React + Vite + Tailwind + framer-motion source for the Web Action (W&A) studio marketing site (Athens). The deployable artifact the user actually uses is a **single self-contained HTML file** with all CSS/JS/images inlined.

**Build steps (Windows-specific gotcha):**
1. `npx tsc -b` then `npx vite build --outDir dist_new --emptyOutDir` — build into `dist_new`, NOT `dist`. `dist/` is locked by Windows (EPERM) and rebuilds fail; this is documented in `inline-build.mjs`.
2. `node inline-build.mjs` — inlines `dist_new` into `C:\Users\mikef\Downloads\web-action.html` (also copy that over the user's `index (4).html`).

**Perf:** all hero/process images are **WebP** in `public/` (earth/logo/logo-sketch/code/result/phone). Originals were ~8MB of PNG → ~1MB WebP, which cut the standalone from 11.7MB to ~1.9MB. Refs carry `?v=N` cache-busters. `result.png` was cropped tight around the monitor so step-03 matches step-02 size; `result.orig.png`/`earth.orig.png` are pre-edit backups.

To preview the standalone: serve `Downloads` with the `wa-standalone` launch.json config (http-server on 5311). Dev server is `web-action-site` (vite, port 5180). See [[web-action-site-mobile-perf]].

**Editing the built `index (4).html` directly (footgun):** the user often drops the standalone in `Downloads` and asks for tweaks edited in-place. Two traps: (1) **Tailwind is purged at build time** — any NEW arbitrary class you add (e.g. `h-[22%]`) has no compiled CSS rule and silently does nothing (collapsed/no-op). Put new styling in the inline `style:{...}` object instead, which always works. (2) The bundle uses backtick template-literal strings and `!0`/`!1` for booleans; match that. (3) Direct edits are **overwritten on the next `inline-build.mjs` rebuild** — for permanent changes, edit the source in `web-action-site` too.

The hero "earth" is a solid bottom-anchored `<img>` (`translate-y-[16%]`, clipped at ~84% of its height on every viewport). **Background architecture (critical):** there's a GLOBAL fixed radial backdrop (`z-[-10]`, `radial-gradient(at 50% 100%, #262626→#000)`, viewport-fixed so its "darkness" shifts as you scroll) plus GLOBAL absolutely-positioned star `<canvas>` layers spanning the whole doc — these show behind BOTH the hero and page-2.

To hide the earth's clipped bottom line, do **NOT** paint an opaque fade-to-black overlay: that flat-black band doesn't match page-2 (which shows stars + the moving gray glow), so a visible seam appears between hero and page-2 on scroll (esp. mobile). Correct fix = **mask the earth img's bottom edge to transparent** so the *same* global backdrop/stars show through on both sides of the boundary → seamless by construction. Current: earth `style.maskImage`/`WebkitMaskImage = linear-gradient(to bottom,#000 0%,#000 75%,transparent 84%)` (solid body, dissolves only the bottom ~9% into space), and the overlay div was removed. If a darker mood is wanted at the bottom, darken the GLOBAL backdrop (affects hero+page-2 equally), never the hero bottom alone.

**iOS Safari mask drop → SOLVED by baking alpha into the image (FINAL approach):** desktop rendered the CSS `mask-image` fine but iPhone (iOS Safari) still showed the hard earth/hero seam — WebKit drops `mask-image` on an element inside a `will-change:transform`/GPU-composited ancestor (the animated hero `K.div`), and the `-webkit-transform: translate3d` isolation hack was unreliable. **The robust fix: stop using a CSS mask entirely and bake the soft bottom fade into the earth WebP's own alpha channel.** Then desktop preview === iOS (it's just an image), so you can verify in the local preview. The earth `<img>` is now CLEAN again (`-translate-x-1/2 translate-y-[16%]`, no mask/style). **Seamless one-page boundary (the user's real goal — no visible line between hero and page-2):** the global StarsBackground (`tm` component, rendered at app root as `pointer-events-none fixed inset-0 -z-10`, sibling of `Wp` hero and `#services`) IS continuous behind both sections, so the ONLY thing that can create a seam is the earth's clipped bottom edge. KEY: bake the earth's alpha to reach **fully transparent right at the clip** (`solid until 62%, transparent by 84%` of image height — the hero clips the img at ~84%), so at the boundary there is zero earth = pure continuous starfield above and below = seamless at rest. Geometry trap: the earth is hard-clipped, so any DOWNWARD sink drags the opaque equator toward the clip and re-creates the line. Resolution = make the opacity-dissolve OUTPACE the sink. Final tuned hero transforms: `r(opacity)=fd(n,[0,340],[1,0])` (dissolves by 340px), `a(y)=fd(n,[0,480],[0,100])` (gentle 100px sink), `i(scale)=fd(n,[0,480],[1,.95])` — the earth melts into the galaxy faster than it sinks, so no firming edge is ever exposed. **FINAL/BEST approach (cross-the-boundary, user's idea):** instead of fading the earth AT the hero's clip (which makes it look pre-faded at rest), let the earth stay SOLID across the hero/page-2 boundary and fade out BELOW it (in page-2's top padding). **iOS filter-box bug — DEFINITIVE FIX = bake the glow into the image, drop the CSS filter.** The `device-outline`/`drop-shadow` CSS filters on transparent lazy-loaded images (the monitors, the logo) render as a hard rectangular BOX on iOS until a repaint (sometimes stays). No CSS workaround (will-change/translateZ) was reliable. The real fix: with `sharp`, build the glow from the device's alpha (extractChannel(3) → tint blue #5a8cff via a solid image + joinChannel → blur at a few radii) + a dark drop-shadow (black silhouette blurred, offset down), composite glow+shadow UNDER the device, export webp. Then on the element set an `imgClassName`/class that does `filter:none!important` (e.g. `.wa-noglow`) so the CSS `device-outline` is overridden. Result: glow is pixels (iOS-proof), no box. Did this for BOTH showcase monitors (steps 2&3, baked at device 1420x952 in 1536x1024 = identical size) AND the hero logo (baked glow in-place, ~34px margin was enough; removed its inline `filter` keeping `willChange:transform`). The hero now has ZERO css filters (verified computed `filter:none` on layer + logo) → fully satisfies "remove filter from hero" + no box. Globe earth dark-ring fix: the radial alpha fade was cutting into the bright atmosphere (dimming it = dark ring); re-bake with the solid radius OUT to the atmosphere edge (`Rin=0.482*W, Rout=0.50*W`) so the bright blue rim is preserved and only the outer dark-space edge fades.

**Reveal-on-scroll animation — SOLVED (2026-07-09, `js/023.js`).** Earlier I thought it wasn't addable; it is. Key facts: framer-motion (baked in) plays the reveal once on MOUNT (off-screen), then holds/contests **opacity, transform, translate, filter** via WAAPI (beats CSS + inline `!important`, re-grabs after `cancel()`), and rule 11 pins `.will-reveal{opacity:1!important}` (opacity locked at 1 = no black-screen but no fade). BUT **framer never touches `clip-path`**, and once framer's mount animation SETTLES (0 active anims, ~1s after load) it releases `translate` too. So the reveal rides on **`clip-path` (inset(0 0 100% 0) -> inset(0 0 0 0), the "appear") + `translate` (0 38px -> 0, the slide)**, set INLINE with an inline transition, driven by a **scroll-position handler** (`window`+`__lenis.on('scroll')`+rAF), NOT IntersectionObserver (IO fires during the compressed load layout and mass-reveals). **Round 5 (2026-07-09): the DEFINITIVE navbar-glitch root cause — the language-toggle gold pill.** Mike kept seeing the EN button "move down 2-3 times on refresh" even after tcHeaderStatic. Verified: pill 0 frames moved over 722 samples, selector matches exactly 1, lang switch works, underlines intact, console clean. LESSON: framer `layout`/`layoutId` animations = inline-transform via rAF (kill with CSS !important); framer `initial/animate` entrances = WAAPI (kill by finishing getAnimations()).

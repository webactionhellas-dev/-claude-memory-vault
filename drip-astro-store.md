How it was done (reuse this recipe):
- **Adapter swap:** `@astrojs/node` → `@astrojs/vercel`. Must pin **v8** (`npm i @astrojs/vercel@^8`) — v11 needs Astro 7, this is Astro 5. Config: `adapter: vercel({ imageService: true })`.
- **`imageService: true` is REQUIRED, not optional.** The homepage is SSR (`prerender=false`); without it, `<Image>` routes through Astro's built-in `/_image` endpoint which **404s on Vercel serverless** (the function can't read the built `/_astro/*.webp` from its filesystem) → every homepage image blank. `imageService:true` switches to Vercel's native `/_vercel/image` CDN (verified 200 image/webp). Prerendered pages (shop/product/brands) were fine either way (pre-generated static images).
- **No secrets shipped:** created `.env.production` (gitignored, overrides `.env` in prod build) with DUMMY placeholders — short `SUPABASE_SERVICE_ROLE_KEY=demo` makes `adminReady()` false so `loadCatalog()` serves bundled `products.json`+assets; dummy `PUBLIC_SUPABASE_URL=https://demo.supabase.co` keeps `createClient()` from throwing at module load; `STRIPE_SECRET_KEY=sk_test_demo` keeps `new Stripe()` happy. No dependency on the live Supabase project.
- **Deploy = prebuilt:** `npx astro build` locally (968 image variants, ~30s) → `vercel link --yes --project drip-store-preview` → `vercel deploy --prebuilt --prod --yes`. Aliases to the clean `.vercel.app` domain automatically. (Node 24→22 runtime warning is benign.)
